# CLI argument reference

Every gBench command-line flag. `gbench --help` prints the same options.

[Back to the README](../README.md)

## Exhaustive CLI Argument Reference

### Model selection
| Argument | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `--models` | `str [str ...]` | None | HuggingFace ids (e.g. `google/gemma-4-31B-it`) or local checkpoint directories; with `--remote-endpoint`, the id that endpoint serves (enriched from `--tokenizer`). A bare name that is neither is refused for a local run. Each id is its own model: ids that share a basename get distinct result names (`org--name`). Size, modalities and context come from the model's own `config.json` (a local directory's own; a Hub id's at the commit it resolves to), recorded in metadata.json (`model_metadata`); a model whose config cannot be read is refused for a local run. |
| `--tokenizer` | `str` | None | Tokenizer/model ID used to build prompts and count tokens. Required in `--remote-endpoint` mode (where no local model is loaded). On a local run whose `--vllm-serve-args` give the server a `--tokenizer`, that one is used when this flag is not given; when both are given they must name the same one. |
| `--tokenizer-trust-remote-code` | flag | `False` | Load the model's tokenizer with `trust_remote_code=True` in gBench's own tokenizer loads (the Golden Set chat-template leak check, prompt counting, the performance pillars' tokenizers), e.g. for a `--remote-endpoint` whose tokenizer ships custom code. On a local run, `--trust-remote-code` in `--vllm-serve-args` already sets it. |
| `--format` | `str` | `hf` | The format a local server serves: `hf` (the HuggingFace checkpoint); `gguf` and `both` are refused. |
| `--served-model-id` (aliases `--golden-model-id`, `--eval-model-id`) | `str` | None | The id the endpoint serves the model under when it differs from `--models`; it must be listed by `/v1/models`. Used by every pillar. Applies with `--remote-endpoint`: the server gBench launches serves the model under its `--models` id or path, so a local run refuses any other value. |

### Benchmark types
| Argument | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `--serving-only` | flag | `False` | Run only serving performance benchmarks. |
| `--throughput-only` | flag | `False` | Run only offline engine throughput benchmarks (a local vLLM engine on a local GPU; refused with `--remote-endpoint`, use `--serving-only` or `--stress-test` there). |
| `--text-only` | flag | `False` | Run text benchmarks only, skipping multimodal tests. |
| `--multimodal-only` | flag | `False` | Run multimodal benchmarks only. |
| `--stress-test` | flag | `False` | Run only the stress test: an open-loop Poisson arrival-rate sweep (x2 per step, stopping at the first failing point), repeated `--stress-reps` times; the median repeat's limit is certified (see `--stress-certify`) or labelled UNCERTIFIED. |
| `--no-stress-test` | flag | `False` | Skip stress testing. |
| `--stress-threshold` | `int` | per-campaign SLO (1000 ms `chat-like` and `decode-heavy`, 2500 `mixed`, 5000 `agentic`, `prefill-heavy` and `long-decode`; 5000 without a campaign) | P99 TTFT SLO in ms for the stress QPS sweep; set, it applies to every campaign. |
| `--itl-slo-ms` (alias `--stress-tpot-threshold`) | `int` | per-campaign SLO (100 ms for every campaign; 200 without a campaign) | P99 inter-token (ITL/TBT) SLO in ms for the stress QPS sweep; a rate is sustainable only if both the TTFT SLO (`--stress-threshold`) and this one hold (100 ms is about 10 tok/s without speculative decoding). The P99 is read from the server's ITL histogram (vLLM `/metrics`, one gap per engine step) when it decides the SLO, else from the client's per-token gap (chunk gaps divided by the tokens each chunk carried), else the client gap between streamed chunks; under speculative decoding the client per-token gap decides (or, with no tokenizer, the server histogram against SLO x tokens per engine step). |
| `--stress-reps` | `int` | `3` (env `GBENCH_STRESS_REPS`) | Sweeps per stress run; each gives a bracket [pass, fail], the headline is the median repeat's limit (then certified), and the result says whether the brackets agree. The flag beats the variable. |
| `--stress-client-procs` | `int` | `min(32, cpu_count-1)` (env `GBENCH_STRESS_CLIENT_PROCS`) | OS processes of the multi-process stress load generator, capped at cpu_count-1; a point the client cannot offer is flagged `client_bound` and excluded. |
| `--stress-max-qps` | `float` | `8192` (env `GBENCH_STRESS_MAX_QPS`) | Safety cap on the open-loop arrival-rate sweep; a server that meets the SLO at the cap has its knee censored there. Raise it together with `--stress-client-procs`. |
| `--stress-max-prompts` | `int` | none (env `GBENCH_STRESS_MAX_PROMPTS`) | Optional cap on requests per stress rate point, recorded when set. By default a point sends max(40, rate x 60 s, rate x (3 x latency + 10 s)) requests (more for certification probes), never fewer. |
| `--stress-min-samples` | `int` | `15` (env `GBENCH_STRESS_MIN_SAMPLES`) | Minimum requests in a point's cohort (the requests planned after its ramp-up) to judge it. Lowering it only makes the bracket sweep cheaper; when certification runs, the reported limit is certified with percentile-sized probes either way. |
| `--stress-certify` | `auto`\|`always`\|`off` | `auto` (env `GBENCH_STRESS_CERTIFY`) | Certify the reported stress limit: inside the sweep's bracket, bisect with probes sized for the P99 SLO (a cohort of >= 1099 requests, about 1400 sent, the same rule on every device) to +-9% when reached (else a certified lower bound with its resolution). `auto` certifies within `--stress-certify-budget`; `always` ignores the budget; `off` reports the bracket, labelled UNCERTIFIED. |
| `--stress-certify-budget` | `float` | `120` minutes (env `GBENCH_STRESS_CERTIFY_BUDGET_MIN`) | Time the certification may take, per stress pass (text and multimodal each); 0 = do not certify (with `--stress-certify auto`; `always` ignores the budget). The budget is checked before each probe: if it runs out after a probe passed, that rate is reported as a certified lower bound; if none passed, the bracket is reported UNCERTIFIED with the time certifying would need (slow single-stream devices can need hours). |
| `--personal` | flag | `False` | Personal-device mode: single-stream, text-only, serving-only, few samples, full decode; reports peak decode tok/s and TTFT. Use with `--remote-endpoint`; incompatible with `--campaign`. |
| `--quality` | flag | `False` | Include GemmaClaw agentic quality suite. |
| `--quality-only` | flag | `False` | Run only GemmaClaw agentic quality suite. |
| `--scenarios` | `str [str ...]` | None | GemmaClaw QA scenario ids to run (not file paths; e.g. `memory-recall mcp-plugin-tools-call`), each passed to the suite as `--scenario <id>`. |
| `--gemmaclaw-path` | `str` | None | Path to a local GemmaClaw/OpenClaw checkout (skips the clone/fetch step; the quality image is built from `git archive` of the commit in it, so uncommitted changes are not used). |
| `--gemmaclaw-commit` | `str` | Pinned default | Git commit of GemmaClaw to provision when no local path is given. |
| `--golden` | flag | `False` | Include Golden Set deterministic capability smoke tests. |
| `--golden-only` | flag | `False` | Run only Golden Set deterministic capability smoke tests. |
| `--golden-tasks` | `str [str ...]` | None | Filter specific Golden Set task IDs or JSON files. |

### Academic and custom evaluations
| Argument | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `--evals` | `str [str ...]` | None | Select evals (`mmlu_pro`, `gpqa_diamond`, `gsm8k`, `aime`, `putnam`, `lcb`, `codeforces`, `mrcr`, `ruler`, `bfcl`, `mmmu_pro`, `screenspot`, `textvqa`, `terminal_bench`, `copilot_bench_swe`, `all`, `plugins`, or custom names). `all` runs every built-in suite except `swe_lancer` and `ui_control_osworld`, which run only when named. |
| `--eval-plugins-dir` (alias `--eval-plugins-path`) | `Path [Path ...]` | None | Directory or Python file path(s) containing custom evaluation plugins (`*.py`). |
| `--eval-custom-jsonl` | `Path` | None | Path to a single custom JSONL benchmark file (see [docs/evals/custom_jsonl.md](evals/custom_jsonl.md)). |
| `--eval-limit` / `--limit` | `int` | None | Run N samples per suite in total (a stratified subset; with `--shard`, drawn from the shard). A sample is one distinct dataset item (question, task, instance, problem, conversation). N is the total for the whole suite, never N per tab, split, setting, language, domain, scenario, pass or mode: a suite with several settings (e.g. swe_bench_live's tabs, bigcodebench's complete and instruct, tau2's domains) spreads the N over them (`sampling.allocate_limit`), and a setting that gets 0 is not run. The attempts a protocol makes per sample (lcb's n=10, arc_agi's 2 attempts, avg@k / pass@k repeats, `--attempt-count`) are unchanged and are not extra samples. Each suite logs its planned workload in one line at its start (e.g. `[swe_bench_live] --eval-limit 5: 5 sample(s) over 5 tab(s) (lite 1, verified 1, ccpp 1, go 1, rust 1) (full, csharp, java, tsjs: 0, not run) x 1 attempt = 5 rollouts`; the last field is the unit total, named for what one attempt is: generations, rollouts, episodes, conversations, ...) and records it in its result as `eval_limit_plan` (`limit`, `samples`, `per_setting`, `attempts_per_sample`, and that unit total, plus a suite's protocol follow-ups such as `repair_calls` or `retry_generations` where it makes them); under `--shard` the plan counts that shard's samples, and a merged run's plan sums the shards'. A suite that discards items by their data alone, before any generation (cimemories' gold labels, gdpval's reference deliverables), draws the N only from the items it can score and records it in `eval_limit_plan`; nothing is ever left out by the model's outcome. Without it every suite runs its full set. |
| `--shard` | `I/N` | None (env `GBENCH_SHARD`) | Run shard I of N of each suite (the full ordered set split round-robin, before `--eval-limit`). Results record `shard`, `shard_index`, `shard_count`; traces a `global_idx` and a shard-independent `sample_key`; a partial shard is not leaderboard-comparable; an empty shard reports accuracy `null` (`empty_shard`); a suite that cannot shard runs its full set and records `shard_applied: false`, and so do the other pillars a run selects (performance, quality, Golden Set), which a warning names and metadata.json lists (`shard_not_applied`). Merge the nodes' results with `--merge`. See [docs/distributed-gbench.md](distributed-gbench.md). |
| `--max-output-tokens` | `int` | **required (eval runs)** | Max generation tokens per eval response. It bounds generation and materially affects scores (truncation reads as a failure), so it must be set explicitly; eval runs **fail fast** without it, rather than silently taking a per-suite default. e.g. `--max-output-tokens 65536`. Official caps follow the token-limit policy (`base.resolve_token_budget`): without `--eval-thinking` a suite whose upstream sampler sends its own max_tokens sends exactly that value, or none when the sampler sends none; with `--eval-thinking` an official cap is not applied, because it was written for non-reasoning generation: the request is sent this flag instead (a per-request cap a suite declares for each sample is replaced the same way, whether it is larger or smaller) and the result records the cap as not applied to reasoning, unless the upstream defines reasoning-model settings, which are then used (never capped below this flag). A reply cut off at an official cap is counted in `replies_at_official_max_tokens` and scored as the upstream scores it; a reply cut off by any other budget is a truncation (lcb, multipl_e, bigcodebench, ojbench, scicode, hmmt, aime, livebench, spider2 (which sends this flag as its own max_tokens) and aider_polyglot count it in `replies_cut_off_by_budget` and report the run as not comparable; aider_polyglot from aider's own `num_exhausted_context_windows`, since aider itself sends no max_tokens (gBench's relay adds this flag)). The judged, vision and long-context suites (chartqa, docvqa, infographicvqa, textvqa, coco_caption, charxiv, mmmu_pro, medxpertqa, wildbench, omnidocbench, simpleqa, browsecomp, healthbench, humanitys_last_exam, frames, imo_answer_bench, aa_lcr, beam_128k, loft_scifact, screenspot, screenspot_pointing, ruler, i18n_translate, bundled_detection), putnam_formal and putnam (whose informal track has no official cap: every request carries this flag) count such replies in `replies_cut_off_by_budget` (`replies_cut_off_in_reasoning` for those with no answer after reasoning) and report the run as not comparable. A suite that does not apply the flag records it in `max_output_tokens_note`. Without `--eval-thinking` these send their upstream max_tokens: mmlu_pro 32768 (TIGER-Lab evaluate_from_apiX.py; the same request is its reasoning-model setting, so `--eval-thinking` sends 32768, or this flag when larger), gpqa, gpqa_diamond, multilingual_mmlu, simpleqa, healthbench and browsecomp 2048 (simple-evals' chat sampler, which a served model takes in both modes: its o-series samplers key on OpenAI model names; with `--eval-thinking` the 2048 is not applied and this flag is sent instead), gsm8k 256 (lm-eval max_gen_toks), causalbench 10, cruxeval 100 (direct prompts), longbench_v2_code 128 (its w/ CoT setting sends 1024 for the CoT query and 128 for the answer query), mmlu_redux 1 (HELM's one-token answer), ruler its per-task caps, lcb 2000 (self-repair included), multipl_e 2048, bigcodebench 1280 (with `--eval-thinking` it follows the openai backend's reasoning-model branch and sends none), livebench 4096 (gen_api_answer.py's --max-tokens default; a served model with a LiveBench config sends that config's cap, e.g. gemma-4-31b-it 65536, also with `--eval-thinking`, never below this flag; LiveBench sends one fixed max_tokens, so a value that would leave the prompt no room in the served window is lowered to fit, and a lowered official cap is not comparable), acebench 1024 (ACEBench model_infer.py LLMInfer, on the single-turn rows and every agent step, within LLMInfer's max_model_len=8192 window as its pinned vLLM 0.6.1.post1 applies it: a request whose prompt leaves less room gets that room, and a prompt longer than the window is not sent, its reply the empty text that vLLM returns), nestful 1000 (NESTFUL src/eval.py --max_tokens default), t_eval 512 (T-Eval test.py HFTransformerCasualLM max_new_tokens=512), chartqa 16, docvqa and infographicvqa 32, textvqa 1024 and coco_caption 64 (lmms-eval's chat client, which runs a thinking model with the same sampling; gBench's thinking runs sample at 1.0, as every `--eval-thinking` run; lmms-eval declares no reasoning-model cap, so with `--eval-thinking` the cap is not applied), charxiv 1000 (CharXiv gpt.py; with `--eval-thinking` this flag: o1.py is keyed on OpenAI o1 model names), mmmu_pro and wildbench 4096, omnidocbench 32000, medxpertqa 2048 (MedXpertQA api_agent.py, the chat branch a served model takes; with `--eval-thinking` the 2048 is not applied and this flag is sent: the 8192 is keyed on o1/o3/qwq/qvq/reasoner model names), gaia 4096 (the reference agent run_gaia.py; with `--eval-thinking` this flag and no reasoning_effort: run_gaia.py's reasoning_effort "high" and 8192 are keyed on its o1 model_id), complexfuncbench 2048 (ComplexFuncBench models/qwen.py, on every turn; with `--eval-thinking` this flag), gaia2 16000 per agent turn (the ARE paper, arXiv:2509.17158; with `--eval-thinking` this flag; applied in its image's hooked ARE engine), toolbench 1024 (StableToolBench's chat_completion_request, on every DFSDT turn), mcp_bench MCP-Bench's own per-call caps (planning rounds and the final answer 12000, tool-result summaries 10000, format fixes 8000, a compression call its target length; mcp_bench and toolbench apply this policy and the thinking switch inside their images) and aa_lcr 16384 (Artificial Analysis's cap for non-reasoning models; with `--eval-thinking` none, the methodology's maximum). ojbench sends none without `--eval-thinking` (the paper gives non-reasoning models their default context length) and 65536 with it (the paper's 64k, or this flag when larger). hmmt and aime send the max_tokens of MathArena's own config for a served model it ships one for (e.g. Qwen/Qwen3.5-27B 192000; with `--eval-thinking` never below this flag); MathArena ships no config for Gemma, so it defines no max_tokens for it; gBench sends --max-output-tokens (its house budget, gBench's choice, not upstream's). These send no max_tokens in either mode, as their harnesses send none: scicode, cyberseceval (PurpleLlama's OpenAI adapter sends none outside its proprietary reasoning-model list), mrcr (the openai/mrcr card's reference loop sends only the model and messages), humanitys_last_exam (HLE's evaluation uses the maximum number of tokens available), lab_bench (LAB-Bench's openai_utils sends only the model and messages), loft_scifact (LOFT GenerationConfig), beam_128k (BEAM's reader; pruning leaves upstream's 2,000-token answer room, or with `--eval-thinking` this flag), screenspot and screenspot_pointing (the reference script uses the model's own generation config), mcp_atlas and cimemories (litellm-strategy.ts payload; CIMemories eval.py), deepsearch_qa (the starter notebook's model call sets none), gdpval (the paper sets none), bfcl and bfcl_live (BFCL's handler sends no max_tokens), seal_tools and api_bank (their chat wrappers send only the model and messages), nexusraven_api_eval (LangChain 0.0.294 OpenAIChat sends only the model and model_kwargs), and gorilla_apibench (get_llm_responses.py sends n=1 and temperature=0 only). The agent suites whose upstream scaffold sends no max_tokens (`swe_agentic.AGENT_MAX_TOKENS_SUITES`: copilot_bench_swe, swe_bench_multilingual, swe_bench_live, multi_swe_bench, swe_bench_pro, swe_lancer, terminal_bench, skillsbench, wildclawbench, gaia2, tau2, tau3, toolbench, agent_dojo, ui_control_osworld, bfcl_v4_agentic, aider_polyglot) send this flag as max_tokens on every agent request that carries no budget (gBench's relay sets it; agent_dojo sets it in its client; a request that carries its own budget, such as gaia2's 16000 or toolbench's 1024, keeps it). Their agents upstream (mini-swe-agent 2.x configs, SWE-agent-for-eval, Win-Agent, MSWE-agent, SimpleAgentSolver, Terminus-2 and LiteLLM, aider for an openai/<id> model, BFCL's handler, AgentDojo's OpenAILLM) send no per-turn cap, so this is a recorded deviation: each result records `agent_max_tokens_from_run` and a `leaderboard_comparable` reason. `GBENCH_AGENT_MAX_TOKENS_FROM_RUN=0` restores the upstream behaviour (no per-turn cap: the server grants each turn what the context window has left); terminal_bench's GBENCH_TB_TURN_MAX_TOKENS stays an opt-in, non-canonical cap. In copilot_bench_swe, swe_bench_multilingual, swe_bench_live and multi_swe_bench a model turn cut at the cap (`finish_reason` length, `truncated_turns`) is counted and makes the run not comparable, and a turn that stopped with reasoning but no content and no tool call or action (`empty_after_reasoning_turns`, the answer inside the thinking channel) is the model's outcome, counted in `answer_in_thinking` / `answer_in_thinking_rate` and not a comparability reason ([answer_in_thinking.md](evals/answer_in_thinking.md)); swe_bench_live and multi_swe_bench count them in gBench's relay, which also records endpoint failures (`endpoint_failures`: harness errors, status `completed_with_errors`). Their one-shot modes apply it. |
| `--eval-concurrency` | `int` | `--batch-sizes[0]` | Concurrent requests per eval suite (the HTTP concurrency of suites that send their own requests); 1 unless `--batch-sizes` or this flag is given. Containerized suites use `--sandboxes` when it is set. |
| `--sandboxes` | `int` | None | Concurrency cap for containerized/sandboxed evals (`terminal_bench`, `putnam_formal`, `aider_polyglot`, the SWE-bench family (`copilot_bench_swe`, `swe_bench_live`, `swe_bench_multilingual`, `swe_bench_pro`, `multi_swe_bench`, `swe_lancer`) plus `bigcodebench`, `multipl_e`, `spider2`, `ojbench`, `tau2`, `tau3`, `skillsbench`, `wildclawbench`, `codeforces`, `lcb`, `scicode`). Lets you run e.g. `--batch-sizes 128` for HTTP evals while capping Docker/sandbox workers to `--sandboxes 64`. Defaults to `--batch-sizes`. NB this caps *concurrency* only; process isolation for code-executing suites is controlled by `GBENCH_SANDBOX` (see [Environment variables](environment-variables.md)). For `aider_polyglot` the value is `benchmark.py --threads`, and all threads share upstream's single 12g benchmark container (upstream's documented run uses `--threads 10`). A run whose container reports an OOM kill, or whose kill count cannot be read, is not comparable (`container_oom_kills`). |
| `--temperature` | `float` | `1.0` with `--eval-thinking`, else `0.0`, for every suite | Global sampling temperature for the model under test across all evaluations and benchmarks. Without this flag gBench applies one rule to every suite: with `--eval-thinking` (alias `--thinking`) the model is sampled at **1.0** (`temperature_source` `thinking`), without it at **0.0** (`temperature_source` `default`). A benchmark's official or upstream temperature is never applied, and gBench always sends a temperature, also to suites whose official harness sends none and to suites whose own harness, agent or container sets sampling (aider_polyglot, the agentic suites), through that harness's own mechanism. Other official sampling fields (top_p, top_k, penalties, seed, stop sequences) are not part of this rule and are kept. A suite that declares its official sampling still records the official values (`official_sampling`). This flag overrides the rule in both modes; a suite whose harness cannot take a value records `temperature_applied: false` on its result. Per-suite override: `GBENCH_<EVAL>_TEMPERATURE` (beats this flag). Judges and user simulators keep their own sampling. |
| `--eval-thinking` (aliases `--enable-thinking`, `--thinking`) | flag | `False` | Let the model think (off by default everywhere). For evals it enables the model's reasoning mode: native suites send `chat_template_kwargs.enable_thinking` on every request, and delegated harnesses that take the toggle forward it (e.g. livebench, aider_polyglot); some suites also change their prompt with it (e.g. cruxeval, screenspot_pointing). For serving it drops the no-think system prompt gBench otherwise sends, so a reasoning model's serving numbers then include its reasoning. |
| `--eval-max-soft-tokens`| `int` | the model's own processor setting | The served model processor's `max_soft_tokens` setting (image soft-token budget) for vision evals on a server gBench launches; refused with `--remote-endpoint`, and for a model whose processor declares no `max_soft_tokens`. Recorded in the evals scaffold. |
| `--eval-n-shot` | `int` | None | Few-shot exemplar count for `mmlu` (dev split, 0-5), `mmlu_pro` (validation split, 0-5) and `gsm8k` (the fixed Wei et al. CoT exemplars, 0-8). Default: canonical 5-shot for mmlu/mmlu_pro and 8-shot for gsm8k; 0 = zero-shot. A larger value is an error. |
| `--eval-categories` | `str` | None | Comma-separated category override, routed per suite: `bfcl` takes any of BFCL's 22 scoring categories (e.g. `simple_python,multi_turn_base,memory_kv`; groups: all, all_scoring, single_turn, non_live, live, multi_turn, agentic, memory, web_search, python, non_python), `bfcl_v4_agentic` its agentic ones (`memory_kv`, `memory_vector`, `memory_rec_sum`, `web_search_base`, `web_search_no_snippet`); `swe_bench_live` its leaderboard settings (`lite`, `full`, `verified`, `ccpp`, `csharp`, `java`, `tsjs`, `go`, `rust`, `windows`; default all ten). A suite that gets no name runs its full track; a name no selected suite knows is an error. Only with `--evals bfcl`, `bfcl_v4_agentic`, `swe_bench_live` or `all`. |
| `--evals-only` | flag | `False` | Run only evaluation suites, skipping performance benchmarking. |
| `--preflight` | flag | `False` | Check every selected suite's prerequisites (its own check, else the local image it names; the Gemini key for the suites that use the Gemini cascade) plus free disk (`GBENCH_PREFLIGHT_MIN_DISK_GB`, default 100), the Docker daemon and the endpoint's `/v1/models` from this host and from a bridge container, all at once and without a model request; prints a PASS/FAIL table and exits 2 on any FAIL. See [docs/smoke.md](smoke.md). |
| `--smoke` | flag | `False` | `--preflight`, then one sample of every suite whose checks passed (`--eval-limit 1`, `GBENCH_SMOKE=1`) as a `--parallel-suites` pool (default 12) behind a recording tap; PASS/FAIL per suite (a reply, the request shape, the agent's follow-up request or the scored sample, a result file), no scores, into `--results-dir/smoke-<timestamp>/`; a hung request (`GBENCH_SMOKE_HANG_S`) and the run's deadline (`GBENCH_SMOKE_DEADLINE_S`, default 3900 s) FAIL the suites they stop; exits 2 on any FAIL. Needs `--remote-endpoint`. See [docs/smoke.md](smoke.md). |
| `--parallel-suites` | `int` | `1` | Run the selected suites as a pool of up to N suite processes (`gbench --evals-only --evals <suite>`), longest first, families kept apart, an admission gate on the server's in-flight requests (`GBENCH_POOL_MAX_INFLIGHT`, default 48), a stall WARNING (`GBENCH_POOL_STALL_S`, default 600); one merged `summary.json` / `eval_summary.csv` in `--results-dir/pool-<timestamp>/`. Needs `--remote-endpoint`. See [docs/smoke.md](smoke.md). |
| `--suite-timeout` | `int` | off | Per-suite wall-clock budget in seconds. A suite that exceeds it is reported as `TIMEOUT` (a failed configuration, exit 2) and the sweep continues; its partial results are lost and its child processes and containers are not reaped, so leave it unset unless running unattended. |
| `--attempt-count` (alias `--attempts`) | `int` | `1` | Independent attempts per sample; results report avg@k, pass@k and pass^k. At temperature 0 the attempts differ only through server nondeterminism. Batch-scored suites that have not opted in run one attempt and say so on the result (`attempts.not_applied`). Multiplies generation cost by k. |
| `--list` | `evals`\|`pillars`\|`presets`\|`golden`\|`models`\|`plugins`\|`all` | None (`evals` when given alone) | List what gBench can run and exit. |
| `--list-plugins` | `PATH` | None (`.` when given alone) | List the evaluation plugins discovered at PATH and exit. |
| `--calibrate` | flag | `False` | Inspect the local hardware (GPUs, their occupancy and VRAM, CPU, RAM, Docker and its network pools), print recommended `--num-gpus` (the idle GPUs; with `--models`, the tensor-parallel size each needs), `--sandboxes` and `--eval-concurrency`, and `Docker networks: N free of M`, and exit. A `--sandboxes` that would over-subscribe the machine (CPU/RAM, or the free Docker networks when `terminal_bench`, `swe_bench_pro` or `swe_lancer` is selected) is refused before a real run (`GBENCH_SKIP_CALIBRATION_GUARD=1` overrides). |

### Workload configuration
| Argument | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `--preset` | `str` | `default` | Configuration preset (`quick` or `default`). |
| `--campaign` | `str [str ...]` | None | Workload campaign (`chat-like`, `agentic`, `prefill-heavy`, `decode-heavy`, `mixed`, `long-decode`). |
| `--dataset` | `str` | `random` | Data source override (`random`, `custom`, `hf`); ShareGPT is run via `--campaign chat-like`. |
| `--dataset-path` | `str` | None | File path or HuggingFace dataset name for `custom`/`hf`. |
| `--num-iterations` | `int` | `3` | Iterations per benchmark config. |
| `--warmup-iterations` | `int` | `1` | Warmup iterations per benchmark config. |
| `--max-cv-percent` | `float` | `5.0` | Max acceptable Coefficient of Variation (CV%). |
| `--batch-sizes` | `int [int ...]` | Auto | Concurrency batch sizes to test. |
| `--input-lengths` | `int [int ...]` | Auto | Input prompt lengths for throughput/serving tests. |
| `--output-lengths` | `int [int ...]` | Auto | Output generation lengths for throughput/serving tests. |
| `--num-prompts` | `int` | None | Advanced fallback prompt count. The serving pillar sizes its own sample count per configuration, so this does not control it (and the flag is refused with `--serving-only`); tune serving with `--batch-sizes` / `--output-lengths` or `--personal`. Throughput uses its own fixed count (1000 with `--preset default`, 10 with `quick`). |
| `--max-model-len` | `int` | performance: `4096` (a `--campaign`'s size with one); evals and quality: the model's native window | Context window of the vLLM server gBench launches. Set it to cap the eval/quality window (e.g. when its KV cache does not fit), or `-1` to let vLLM fit the window to GPU memory. A positive value must exceed `--max-output-tokens`. |
| `--num-gpus` | `int` | **required (local runs)** | GPU count of the vLLM server a local run launches (every local run launches one: performance, quality, Golden Set, evals); omit only with `--remote-endpoint`. |
| `--tensor-parallel` | `int` | `--num-gpus` | vLLM tensor parallel size: 1, 2, 4, 8 or 16, at most `--num-gpus`; `--num-gpus` must be a multiple of it, the rest being data-parallel replicas (`--data-parallel-size`). |
| `--gpus` | `str` | idle GPUs | Comma-separated GPU indices or UUIDs a local server runs on (as many as `--num-gpus`, each running no other process). Default: the first idle GPUs (no compute process, at least 80% of memory free) among those `CUDA_VISIBLE_DEVICES` exposes; too few is an error. The server gets `CUDA_VISIBLE_DEVICES` set to the chosen UUIDs; metadata.json records them. See [GPU selection](performance.md#gpu-selection). |
| `--tool-call-parser` | `str` | None | The model's vLLM tool-call parser: the eval, quality and Golden Set server gets `--enable-auto-tool-choice --tool-call-parser NAME`. Required for a local run of a suite that sends native tools (marked `[tools]` in `--list evals`), the quality pillar, or the Golden Set's tool cases; refused with `--remote-endpoint`. Recorded in the scaffold. |
| `--reasoning-parser` | `str` | None | The model's vLLM reasoning parser for the same server (`--reasoning-parser NAME`), so a `--thinking` reply separates its reasoning from its answer. Required for a local `--thinking` run of the evals or the quality pillar (without it the server returns the reasoning inside the answer text); `--reasoning-parser none` states that the model has none (nothing is passed to vLLM; the scaffold records `none`). Refused with `--remote-endpoint`. Recorded in the scaffold. |
| `--vllm-serve-args` | `str` | None (env `GBENCH_VLLM_SERVE_ARGS`) | Extra `vllm serve` arguments for every server gBench launches (one quoted string, shell-split, appended last; written with `=` since the value starts with `--`, e.g. `--vllm-serve-args='--trust-remote-code'`). Recorded in the scaffold. |
| `--remote-endpoint` | `str` | None | Remote OpenAI-compatible endpoint; normalized once to end in `/v1` for every pillar. |
| `--gpu-memory-utilization`| `float`| `0.90` | vLLM server VRAM utilization fraction. |

### Output and execution controls
| Argument | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `--results-dir` | `Path` | `./results` | Destination directory: each run writes its own `<timestamp>` directory under it; an existing run directory is continued in place by one run at a time (see [Output Directory Structure](results.md#output-directory-structure-and-result-schemas)). |
| `--tags` | `str [str ...]` | None | Metadata tags assigned to run outputs (`key:value`). |
| `--skip-existing` | flag | `False` | Reuse a previous result for a suite instead of running it. A cached result under `--results-dir` is reused only if all of these hold: it records the same `canonical_sync` stamp and the same `run_shape` (temperature, `--max-output-tokens`, `--eval-thinking`, `--eval-limit`, shard, `--eval-n-shot`, soft tokens, `--attempt-count`, routed categories, served id and window, judge and search cascades, serve settings, the suite's run-shaping env knobs, the custom JSONL's sha256); it has the same evals `scaffold_id`; and its status is `success` or `completed_with_errors`. Newest means the result's own `finished_at` stamp. A result that cannot be read, or that has no `run_shape` (written by an older gBench), is never reused and the suite re-runs; a reused result records `reused_from`. Off by default; a reused result is measured by whatever the code was then, not now. Opt in only to resume an interrupted run against unchanged code. |
| `--merge` | `DIR [DIR ...]` | None | Merge the eval results of a sharded run (each DIR one node's results directory) into a new `--results-dir/merged-<timestamp>/` of its own (`-2`, ... when the name is taken); a refusal writes nothing, and with `--dry-run` the shards are checked and merged and nothing is written; see [docs/distributed-gbench.md](distributed-gbench.md). Unsharded runs of different suites (each suite once) are joined instead: the files copied unchanged, one `summary.json` and `eval_summary.csv` over all of them ([docs/smoke.md](smoke.md)). |
| `--eval-provenance` | flag | `False` | Print each suite's canonical-sync provenance (the date it was last reconciled with its upstream, and whether it is pinned to a revision or checksum) and exit. See [Provenance and comparability](results.md#provenance-and-comparability). |
| `--no-skip-existing` | flag | n/a | Explicitly re-run every benchmark (the default). |
| `--dry-run` | flag | `False` | Preview the execution plan without starting servers: the planned conditions, and per model each server's `vllm serve` command, port, GPUs and base URL. Validates `--num-gpus` / `--tensor-parallel` / `--gpus` and the sandbox concurrency as the real run would (exits 2 when the real run would fail); a busy GPU is advisory. |
| `--verbose` | flag | `False` | Enable verbose debug logging. |
| `--version` (alias `-v`) | flag | n/a | Print the gBench version and exit. |
| `--timeout` | `int` | `600` | Per-request serving timeout in seconds on both remote paths: a per-read stall timeout for text requests, a total wall-clock cap for multimodal ones. |
| `--mm-probe-timeout` | `int` | `10` (`120` with `--personal`) | Seconds to wait for the remote multimodal capability probe; raise it if a capable but slow endpoint is detected as text-only. An inconclusive probe (an endpoint failure) runs the multimodal pillars, whose failures are then harness errors. |
| `--min-free-gb` | `float` | model-aware, advisory | Minimum free VRAM per GPU in GB; replaces the model-aware weights-fit advisory with a hard free-memory pre-check (for non-datacenter GPUs). |
| `--stage-to-gcs` | `str` | None | Upload each model's checkpoint to the GCS destination (`<dest>/<short_name>/`): its local directory, else a snapshot of its HuggingFace repo. A model that fails is logged and the run exits 2. |
