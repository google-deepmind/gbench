# Environment variables

The environment variables gBench reads. Per-suite knobs are listed in [evals/env-knobs.md](evals/env-knobs.md).

[Back to the README](../README.md)

## Environment variables

gBench supports the following environment configuration variables:

| Variable | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `VLLM_API_KEY` | `str` | None | The served endpoint's key (`OPENAI_API_KEY` is read as an alias when it is unset; placeholder values such as `EMPTY` or `dummy` are ignored: `base.endpoint_api_key`). gBench's own process sends it as `Authorization: Bearer <key>` on the requests it makes to the endpoint: every request of the suites that run through `base.run_eval_suite`, the `/tokenize` and `/detokenize` calls, the Golden Set and quality pillars, and gBench's endpoint relays for container suites, which add it host-side (it never enters a container that runs model-written code or the model's tool calls); also the serving and stress pillars' requests (to a remote endpoint or the server gBench launched; the local text benchmark passes it to vLLM's benchmark client, which otherwise sends only `OPENAI_API_KEY`), the multimodal preflight, the endpoint preflight (a 401/403 on `/v1/models` is a hard failure, never passed by `/health`), the served-model listing and the multimodal probe. The server gBench launches is started with `VLLM_API_KEY` set to exactly this value (surrounding whitespace stripped); a placeholder value is removed from its environment, so it enforces no key. Performance results record `server.endpoint_key_enforced` (never the key). |
| `GBENCH_GCP_AUTH` | `1` / `true` / `yes` | unset | Opt-in GCP identity-token auth, used only when no `VLLM_API_KEY` / `OPENAI_API_KEY` is set: the Golden Set fetches a token with `gcloud auth print-identity-token` for a remote endpoint (never for `localhost`, `127.0.0.1` or `0.0.0.0`), and the quality pillar, for a `*.run.app` or `*.googleapis.com` endpoint, asks the metadata server and then gcloud. Unset, gBench makes no metadata-server or gcloud call. The endpoint check at the start of every remote run sends no identity token, so an IAM-protected endpoint stops the run there (see Cloud Run endpoints under [Remote endpoint mode](remote-endpoints.md#remote-endpoint-mode---remote-endpoint)). |
| `GBENCH_SERVER_HOST` | `str` | `127.0.0.1` (performance servers, and the quality / Golden Set server of a run that selects no eval suite); all interfaces (the server of a run that selects eval suites) | The bind address (`--host`) of every server gBench launches. It must be a loopback address (127.0.0.0/8, `::1`, `localhost`) or all interfaces (`0.0.0.0`, `::`): gBench reaches the server at 127.0.0.1, and any other value is refused before a server starts. Unset, a run that selects eval suites binds its server to all interfaces so the suites whose containers run on docker's default bridge reach it at the bridge gateway (`172.17.0.1`); a run that selects none binds it to `127.0.0.1`, since quality and the Golden Set reach it from gBench's own process. The address and the reason are recorded in `result['server']['host']` and `result['server']['host_source']` of performance results, and eval, quality and Golden Set results record the server they ran against in `result['server']` too. |
| `GBENCH_VLLM_BIN` | `str` | `<python> -m vllm.entrypoints.cli.main` | Replaces the vLLM command of every server gBench launches (shell-split); results record `server.vllm` / `run_fingerprint.vllm`. A server started this way is checked by its model listing only. |
| `GBENCH_SERVER_PORT` | `int` | first free port from `8000` | The port of the vLLM server gBench launches (`config.resolve_server_port`). Set: that port, and a port another process holds is an error (never another port); unset: the first free port from 8000, and an automatically chosen port another process takes before the server binds it is retried on the next free one (up to 3 attempts). Once the server answers, gBench checks the process on the port is its own server. |
| `GBENCH_VLLM_SERVE_ARGS` | `str` | None | Extra `vllm serve` arguments for every server gBench launches, read when `--vllm-serve-args` is not given (the flag wins; same refusals). |
| `GBENCH_SHARD` | `I/N` | None | The run's shard when `--shard` is not given (e.g. set per swarm node); a malformed value is an error. See [docs/distributed-gbench.md](distributed-gbench.md). |
| `CUDA_VISIBLE_DEVICES` | `str` | all GPUs | Limits the GPUs gBench considers for a local server (indices or UUIDs); `--gpus` then picks among them, else the first idle ones do. |
| `HF_TOKEN` | `str` | None | HuggingFace Hub authentication token for gated model/dataset downloads. |
| `GEMINI_API_KEY` | `str` | None | API key for the LLM judge used by judged eval suites (`simpleqa`, `frames`, `browsecomp`, `humanitys_last_exam`, `healthbench`, `putnam_formal` (no-answer answer review), `acebench` (agent_multi_turn user simulator; without the key only that category is reported infra_required and the other categories run), `tau2` / `tau3` (user simulator and judge; tau3's retrieval embeddings with `gemini-embedding-001`), ...); a comma/semicolon-separated key list may be set as `GEMINI_API_KEYS` instead, and `GEMINI_API_KEYS` wins when both are set. Those suites **hard-error** (never skip, never downgrade to a heuristic) if neither is set, so a judged suite is never scored on fabricated data. Every model role a harness has (judge, grader or rater, labeler, user or API simulator, web search / grounding, embeddings) goes through the Gemini API only; a benchmark's non-model tool backends (toolbench's real-API proxy, api_bank's Translate, complexfuncbench's Booking.com RapidAPI tier with `RAPID_API_KEY`, mcp_bench's and mcp_atlas' server APIs with their own keys, mcp_atlas' exa and oxylabs page tools included) run as upstream runs them, and a missing key or unreachable backend is `infra_required` for that suite or setting, never a Gemini substitution (the list, with each suite's keys: the Gemini scope in [env-knobs](evals/env-knobs.md)). Where a model role differs from the official service (for example the Gemini Google Search grounding behind `bfcl`'s web_search, `mcp_atlas`' search tools and `wildclawbench`'s web_search, or tau3's embeddings), the result records the substitution and is not leaderboard-comparable. |
| `GBENCH_JUDGE_MODELS` | `str` (csv) | `gemini-3.8-flash`, `gemini-3.7-flash`, `gemini-3.6-flash`, `gemini-3.5-flash`, `gemini-3.1-pro-preview` | The one Gemini model cascade (comma-separated, tried in order) for every Gemini text role: LLM judges, graders and raters, labelers, user simulators (tau2 / tau3, acebench, toolbench's API simulator), web search / grounding (unless `GBENCH_SEARCH_MODELS` is set), and the judges inside the gaia2, wildclawbench, mcp_bench and toolbench containers, which gBench hands the list at run time. The default is `base.GEMINI_CASCADE`. Every judged suite checks before it runs that the Gemini API serves each model of the cascade to the key, and hard-errors `infra_required` naming a missing or mistyped model and the variable to fix. When every model fails every round, a judged sample is recorded as a `JUDGE_OUTAGE` (a harness error: excluded from accuracy, never scored 0). Results record which Gemini model answered (`gemini_models_answered` for replies of gBench's shared judge call, and per verdict where a suite records it). Not used for tau3's retrieval embeddings (`gemini-embedding-001`) or the quality pillar's pinned helper models. |
| `GBENCH_JUDGE_MODEL` | `str` | None | A one-model cascade, read only when `GBENCH_JUDGE_MODELS` is unset or empty (`GBENCH_JUDGE_MODELS` wins when both are set). |
| `GBENCH_SEARCH_MODELS` | `str` (csv) | the `GBENCH_JUDGE_MODELS` cascade | Replaces the cascade for web search / grounding only (`GBENCH_SEARCH_MODEL`: one model). |
| `GBENCH_SANDBOX` | `required`\|`bwrap`\|`none` | `required` | Process isolation for suites that execute model-written code (`codeforces`, `cruxeval`, `lcb`, `scicode`; `multipl_e` runs inside its Docker evaluator instead, and `acebench`'s BinOp evaluator always runs in its own bubblewrap container whatever this is set to: its own user, PID, IPC, UTS, network and cgroup namespaces, no `/proc`, no `/run` or Docker socket, only the interpreter's directories on its root; it hard-errors when bubblewrap is unavailable; `nestful`'s Win Rate worker also always runs in a bubblewrap container of its own, isolated the same way, with only `PATH` and `HOME=/tmp` in its environment and the reference functions read-only on its root; without a working bubblewrap the Win Rate alone is `infra_required`). `required` (default) runs each step through [bubblewrap](https://github.com/containers/bubblewrap) (read-only root, private `/tmp` and `/run`, so no Docker socket, no network, new PID, IPC and UTS namespaces with a `/proc` of its own, no capabilities, and credential files hidden: the home directory is replaced by an empty one into which only the interpreter's directories, the Hugging Face hub cache and `GBENCH_SCICODE_TEST_DATA` are bound back read-only, and for scicode the vendored `scicode` package its test cases import (`gbench/third_party/_scicode_vendor`), also where a symlink inside the home leads to them (a home that is one of the interpreter's prefixes or lies inside one is not emptied: it stays, with a warning, and only its credential files are hidden), and credential files elsewhere, such as `GOOGLE_APPLICATION_CREDENTIALS`, `CLOUDSDK_CONFIG`, `DOCKER_CONFIG` and huggingface_hub's token files, are hidden); model code never runs unsandboxed by default. In every mode, `none` included, the program gets an environment without the credential variables (the names and suffixes listed in [env-knobs](evals/env-knobs.md)) and without any variable whose value carries a credential (with `none` nothing else is isolated). Canonical code-executing suites (e.g. `codeforces`) **hard-error** if bubblewrap is unavailable rather than reporting a fake 0%. `bwrap` requires it and **fails loudly** if unavailable (strict CI gate); `none` runs on the host (explicit opt-out). Install with `apt install bubblewrap`. Distinct from `--sandboxes`, which only caps concurrency. The quality runner's QA suite always runs in gBench's own Docker container (no network, read-only root, the suite run as a user without capabilities), whatever this is set to; see [docs/quality.md](quality.md). |

Every per-suite knob follows the `GBENCH_<SUITE>_<KNOB>` convention (older bare-prefixed names such as
`TAU2_*` / `SCICODE_*` still work as deprecated aliases). The full list, including the cross-cutting
decoding, judge, and search knobs, is in the consolidated reference:
**[`docs/evals/env-knobs.md`](evals/env-knobs.md)**.

**A suite that cannot produce a trustworthy number hard-errors, with the reason on the result.** It never reports a guessed or zeroed score. Such a suite, like one that raised any other error, exceeded `--suite-timeout` or returned without a score, is a failed configuration: its accuracy is withheld (`null`, with `accuracy_withheld_reason`), the summary table prints `INFRA REQUIRED`, `ERROR` or `TIMEOUT` in place of its numbers (eval_summary.csv: `-` for the accuracy and the failure kind as the status), summary.json counts it in `failed_configurations`, and the run exits 2 (a harness error, not a verdict on the model; see [Exit codes](results.md#exit-codes)). Each blocked suite's setup page under [`docs/evals/`](evals/) explains what it needs; a suite whose canonical harness is not implemented yet is **deregistered and tracked roadmap-only** in [`docs/evals_roadmap.md`](evals_roadmap.md) rather than shipping a runnable placeholder. An implemented suite whose prerequisites most hosts cannot provide (`/dev/kvm` for `ui_control_osworld`, a harness that edits the Docker host's iptables rules and pulls about 1.3 TB of task images for `swe_lancer`) stays registered, is left out of `--evals all`, runs when named, and hard-errors naming the missing prerequisite.

Every optional dependency (Python extras, language toolchains, Docker, sandboxing and the
harness variables below) is listed with its install command and the suites that need it in
**[`docs/evals/toolchains.md`](evals/toolchains.md)**.

Several execution-based eval suites read their own opt-in / asset-location variables and hard-error when unset (see the suite guides under [`docs/evals/`](evals/)):

| Variable | Used by | Description |
| :--- | :--- | :--- |
| `GBENCH_SPIDER2_REPO_DIR`, `GBENCH_SPIDER2_GOLD_DIR`, `GBENCH_SPIDER2_LOCALDB_DIR` | `spider2` | A local xlang-ai/Spider2 checkout at the pinned commit cafb8673 (metadata, gold results) + the SQLite databases; the run records the checked-out commit (the bare SPIDER2_* names are deprecated aliases). |
| `GBENCH_OJBENCH_TESTDATA` (legacy alias `OJBENCH_TESTDATA`) | `ojbench` | Path to the OJBench NOI/ICPC testdata snapshot. |
| `GBENCH_SWE_LANCER_IMAGE`, `GBENCH_SWE_LANCER_TRAJ_DIR` | `swe_lancer` | Name of the locally built SWE-Lancer harness image (default `gbench-swe-lancer-harness:51052ced`) and the parent of its run directory (default `<run results dir>/agent_trajectories`). |
| `GBENCH_SWE_BENCH_LIVE_WIN_AGENT_DIR`, `GBENCH_SWE_BENCH_LIVE_HARNESS_DIR` | `swe_bench_live` | Windows tab only: checkouts of Win-Agent (47d85cff) and microsoft/SWE-bench-Live (62d02936, with its launch submodule) on a Windows Docker host. |
| `GBENCH_OSWORLD_VM_DIR`, `GBENCH_UI_CONTROL_OSWORLD_IMAGE`, `GBENCH_UI_CONTROL_OSWORLD_TASK_IMAGE` | `ui_control_osworld` | Directory holding `docker_vm_data/Ubuntu.qcow2`, the locally built orchestrator image (default `gbench-ui-control-osworld:fc31a904`) and the task VM image (default `happysixd/osworld-docker`, which must be the pinned digest sha256:0e6497a9, see [docs/evals/ui_control_osworld.md](evals/ui_control_osworld.md) step 4). |
| `GBENCH_SWE_BENCH_PRO_IMAGE`, `GBENCH_SWE_BENCH_PRO_TASK_HOST` / `GBENCH_SWE_BENCH_PRO_TASK_ENDPOINT`; `GBENCH_SWE_BENCH_PRO_HARNESS_DIR` only for the maintained-engine route (the bare names remain deprecated aliases) | `swe_bench_pro` | V2 harness image (no opt-in needed); the v1 harness checkout is read only when `GBENCH_SWEBENCH_PRO_AGENTIC=1`. `GBENCH_SWE_BENCH_PRO_TASK_HOST` is where gBench's relay listens (default `172.17.0.1`): the task sandboxes reach the endpoint only through it, with `OPENAI_API_KEY=EMPTY` (the relay adds the endpoint key, `VLLM_API_KEY` else `OPENAI_API_KEY`, when one is set, and the endpoint failures it counts are harness errors), so `GBENCH_SWE_BENCH_PRO_TASK_ENDPOINT` is not used by the V2 locked protocol or the one-shot mode. |
| `GBENCH_MINI_SWE_AGENT_V2_IMAGE`, `GBENCH_SWEBENCH_V5_IMAGE` | `copilot_bench_swe`, `swe_bench_multilingual` | Names of the locally built mini-swe-agent 2.x rollout image (default `gbench-mini-swe-agent-v2:2.4.2-2.4.6`) and swebench 5.0.2 harness image (default `gbench-swebench-v5:5.0.2`). |
| `GBENCH_SWE_BENCH_LIVE_AGENT_IMAGE`, `GBENCH_MULTI_SWE_BENCH_AGENT_IMAGE` | `swe_bench_live`, `multi_swe_bench` | Names of the locally built SWE-agent-for-eval rollout image (default `gbench-sweagent-for-eval:82422422-rex3`) and MSWE-agent rollout image (default `gbench-mswe-agent:88217624`). |
| `GBENCH_TAU2_IMAGE` | `tau2`, `tau3` | Local tau2-bench image the suites run in (default `gbench-tau2:b7ea9074`, built with `docker build -t gbench-tau2:b7ea9074 -f docker/tau2.Dockerfile docker/tau2_srt`). Without Docker or the image both suites hard-error with that command. |
| `GBENCH_GAIA2_IMAGE`, `GBENCH_GAIA2_MODEL_ENDPOINT` | `gaia2` | Pinned Meta ARE orchestrator image + optional model-endpoint override. `gaia2` runs canonical when Docker, the image, and `GEMINI_API_KEY` are provisioned; otherwise it hard-errors `infra_required`. |
